# render-worker

Implements §6.1 stages 7–14 — clip extraction, face-centered 9:16 crop
(§6.3), word-pop ASS captions (§6.4), optional branding overlay, final
H.264/AAC encode, and a thumbnail. FastAPI HTTP service, same shape as the
other workers: NestJS's `RenderProcessor` POSTs a job to `/jobs/render`;
this service does the work and POSTs the finished (or failed) Short record
to `/api/v1/shorts`.

## Run locally

```bash
cd services/render-worker
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
uvicorn main:app --reload --port 8003
```

Or via `infrastructure/docker/docker-compose.yml` (`render-worker` service).

## Status

✅ Implemented (Day 7–10 of the roadmap — the "first playable Short"
milestone). See `PR-03-NOTES.md` in the repo root for the full design
rationale, including:

- **Branding** uses a single FFmpeg overlay filter instead of MoviePy —
  there's no Settings UI yet to actually upload an org logo, so this path
  is mostly untested in practice until that ships.
- **Thumbnail** is a plain FFmpeg frame grab — no Pillow text overlay yet.
- **Short id** is pre-generated by the API (`ClipsService.approve()`)
  *before* this worker runs, specifically so the `renders/{shortId}/...`
  S3 path is known up front.
